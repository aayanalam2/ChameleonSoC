# ChameleonSoC

A small RISC-V SoC that reconfigures an embedded FPGA fabric at run time.

An RV32I core runs a program that writes a bitstream to a memory-mapped Fabric
Control Block (FCB) over a Wishbone interface. The FCB shifts the bitstream into
the configuration chain of an eFPGA fabric generated with
[OpenFPGA](https://github.com/lnis-uofu/OpenFPGA), checks it with an Adler
checksum, and then releases the fabric to run the logic it was configured with.

Everything here is verified in simulation with Icarus Verilog. Nothing has been
synthesized, placed and routed, or taped out.

## What works

Running the testbench configures the fabric with a two-input OR gate and then
exercises it:

```
=== CONFIGURATION SUMMARY ===
Total bits shifted: 2035

=== TEST RESULTS ===
Total tests:   100
Passed tests:  100
Failed tests:  0
OVERALL: PASS - All tests passed!
```

## Running it

Needs `iverilog` and `vvp`, and `gtkwave` if you want to look at waveforms.

```bash
make        # compile RISCV.v and tb.v into simv
make run    # run the simulation, takes a few minutes
make plot   # open waves.vcd in GTKWave
```

The run writes a `waves.vcd` of about 90 MB, so it is not committed.

## Layout

| Path | What it is |
| --- | --- |
| `RISCV.v` | Top module. Wires the core, memories, memory controller and FCB together. |
| `ALU.v`, `RegisterFile.v`, `InstructionDecoder.v`, `immediateGenerator.v`, `BranchComparator.v`, `PC.v`, `PCplus4.v` | The single-cycle RV32I datapath. |
| `MasterMemoryController.v` | Routes loads and stores either to data memory or to the FCB's Wishbone registers. |
| `FCB.v` | Fabric Control Block. Holds the control, status, bitstream and checksum registers, drives the configuration chain, and gates the fabric clock until configuration finishes. |
| `FabricControlBlock.v`, `shiftreg.v` | Supporting logic for the configuration path. |
| `dMem.v`, `Program_memory.v` | Data and instruction memory, both initialized with `$readmemh`. |
| `SRC/` | The eFPGA fabric, generated by OpenFPGA. Not hand-written. |
| `TestInstructions/` | Test programs in hex. `Program_memory.v` loads `FCBTest.txt` by default. |
| `PythonHelpers/` | Scripts for reformatting and comparing bitstreams. |
| `tb.v` | Testbench. Configures the fabric, then drives 100 input combinations at the OR gate and checks each result. |

To run a different program, point the `$readmemh` in `Program_memory.v` at another
file in `TestInstructions/`.

## Limitations

- The core is single-cycle. It is not pipelined.
- The fabric is small, and the demonstration logic is a two-input OR gate.
- Simulation only. There are no timing, area or power numbers.
- Data memory is initialized from `output.txt`, which is a fixed image rather than
  something the build produces.

## Background

Built as a final year project at NUST SEECS. The goal was to find out what a
processor actually needs in order to treat a reconfigurable fabric as a device it
can program at run time: the register interface, the configuration sequencing, and
a way to tell whether the bitstream arrived intact.
